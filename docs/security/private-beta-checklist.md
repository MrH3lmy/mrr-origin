## How to use this checklist

- Every open item should have a linked GitHub issue before private beta starts. Items 2, 6, and 7
  had open product/architecture decisions posted on #27; those decisions were accepted, implemented,
  and verified (see each row's notes and `docs/security/threat-model.md` §§2 and 5) — all three are
  now `Done` as of PRs #79, #78, and #76 respectively.
- "Done" items are not one-time: re-verify item 1 (cross-tenant isolation) on every PR that adds a
  new repository or endpoint family, per `ARCHITECTURE.md`'s tenancy rules — that requirement does
  not expire when this checklist is checked off once.
- Remaining open items (9, 11, 13, 14, 15) are **not** part of #27's own acceptance criteria — #27
  scoped a threat-model audit, export/deletion implementation, and checklist/incident-contact
  documentation, all of which are now complete. They remain genuine open gates before the private
  beta *launch* decision (#29) and are each owned outside #27:
  - **9 (Dependabot alerts/security-updates toggles) and 11 (secret-scanning push protection):**
    one-click GitHub repository-admin actions under Settings → Code security. Not code-configurable
    from a PR; no dedicated GitHub issue exists for these as of this audit (2026-08-19) — they are
    tracked here and require `@MrH3lmy` (repo admin) to enable them directly.
  - **13 (KMS/secrets-manager selection) and 14 (production identity-provider selection):** deferred
    architecture decisions per `ARCHITECTURE.md` → Deferred decisions, each requiring an ADR before
    implementation per `AGENTS.md`. No dedicated GitHub issue exists for either as of this audit;
    they require an explicit product/infra decision from the repository owner, not more agent-side
    investigation.
  - **15 (load and failure-recovery tests):** owned by #28, not #27. Decomposed into narrower child
    issues as part of the #27 close-out audit — see #28 for the proposed slices.
